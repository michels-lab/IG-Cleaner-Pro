# GRANADA P0 — Final stable release must install and validate Android Developer

**2026-10-21 owner authorization:** GRANADA may include a definitive stable release for the named app after every required gate passes. **No RC or beta.**

## Hazard identified
The official publisher previously required exact-SHA Desktop/Android Home+About evidence and installed Windows public+Developer Setup tests, Android Developer signed output and asset presence, **but did not actually require the installed Developer APK's Account navigation, section-note persistence and native JSON export emulator suite**. Standalone Android Developer PR #184 run `39603960666` failed TWICE at `DeveloperEditionTest.realDeveloperBuildSupportsAccountNotesAndRestart` while its signer and isolation tests passed. Without a new publisher gate, an otherwise green release could wrongly ship a Developer APK with failing Account access.

## Implemented safeguard
1. `.github/workflows/release.yml` adds `android-developer-qa`, an actual installed Android emulator test job using **the same exact checkout SHA as the final release request**; it runs governed Developer package checks, installs public + Developer with separate IDs, tests owner Account screen and section annotations after restart, exports actual JSON in Android Downloads.
2. `publish` now explicitly `needs` that job and requires `needs.android-developer-qa.result == 'success'`. A failed, skipped, canceled or unavailable emulator job blocks publication. The CI disposable signer never replaces real stable keystore/provenance requirements in the `publish` job.
3. Privacy-safe emulator logs/artifacts are retained for diagnosis. No social-account credentials or relationship-changing Instagram clicks. Publisher remains disabled when release-request.json is already published/unauthorized; no version bump or release invoked by this branch.
4. Both `tests/release-publisher-contract.py` and `tests/developer-release-contract.py` now require the new mandatory job, install command, saved evidence and explicit publisher dependency, protecting against regression.

## Acceptance / status
- Test contract execution: same-SHA CI must verify both contracts, Android package signing and workflow semantics. Existing code or a green Windows UI screenshot is not proof Developer sign-in works.
- Installed Developer emulator acceptance still blocked in PR #184 until source root cause is diagnosed/fixed; separate PR #185 adds exact WebView route diagnostic without overriding production.
- Release remains **official stable v120.54**; no v120.55 request/tag/assets generated by this work. The standing owner authorization is conditional; a red Developer Account suite must stop publication.
