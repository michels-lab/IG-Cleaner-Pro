# Independent Windows startup slot availability

2026-11-24. Previously the native chooser always offered both slots, including an already-running window, then failed later at the authoritative mutex. Now it reads existing named mutexes without creating them, offers only available slots, explains occupied/unavailable slots, and offers Cancel even if both are occupied. Production and Developer mutex namespaces are separate. The actual launch still atomically reserves the selected mutex, so a competing startup cannot create duplicate windows. No account login, Chrome profile migration, browser data write, or Instagram call is made by the chooser. Negative regressions cover both occupied, each occupied, cancellation and stale/unavailable selection; native Windows runtime probe tests the real mutex lifetime. Physical two-account owner acceptance #377 remains pending. Separate from immutable v120.82 publisher. P0 58% (7/12).

## P0 #416 — installed v120.82 startup regression

Owner's normal startup failed before selecting any account. Confirmed source ABI mismatch: Windows task-dialog structs are byte-packed (Microsoft Windows Rust bindings: https://microsoft.github.io/windows-docs-rs/doc/windows/Win32/UI/Controls/struct.TASKDIALOGCONFIG.html ; SDK-style header: https://chromium.googlesource.com/chromium/deps/perl/+/master/c/i686-w64-mingw32/include/commctrl.h). Original ctypes default padding was incompatible on 64-bit Windows; exact HRESULT on owner's machine unavailable. Correct packed layout is 160 bytes on x64 (8 fixed 32-bit fields, 16 pointer-sized fields), button 12 bytes. Initial regression assertion incorrectly expected 152 bytes, resulting in two red CI jobs; corrected assertion, no product-gate waiver. Signed HRESULT and explicit fallback via MessageBoxW preserve account choice/cancel without silently switching identity. Packaged installer now must exercise both real TaskDialogIndirect account buttons and Cancel using its native message callback, then the existing primary/secondary startup tests. This is not physical owner proof. No data paths or account data changed. Latest stable remains v120.82 until separately governed replacement. #413 is independent and not part of this P0 fix.
